# Strip code comments, deterministically

**Read a comment, decide, name its line.** The script does the cutting and
proving. Judgement is yours; excision is mechanical and must never be done by
hand, because it risks silent corruption (a `#` inside a `run: |` block is
shell **content**, not a comment).

## The gate

For each file: normalise, edit, normalise again. Each normaliser discards
comments and preserves everything else, so an identical normal form before
and after proves the edit removed comments and nothing else; a file that
stops parsing, or whose normal form moves, is **restored** and reported.

| ext | normal form | why it proves the strip is safe |
|---|---|---|
| `.py` | `ast.dump(ast.parse(...))` | comments aren't AST nodes |
| `.sh` | `shfmt -mn` | minified, comments dropped; here-doc bodies kept verbatim |
| `.nix` | `nix-instantiate --parse` | comments discarded at parse |
| `.ts .tsx .js .jsx .mjs .cjs` | TypeScript scanner token stream | comments are trivia, never tokens |
| `.cs` | own scanner → code/string/preprocessor record stream | no C# parser available; scanner proves its own inventory |
| `.rs` | own scanner, whitespace collapsed to one space | doc comments are `#[doc]` attrs, kept verbatim |
| `.yml .yaml` | `safe_load_all` → sorted JSON | comments aren't data |

A **REVERTED** file is a language-module bug, not an acceptable loss. Diff it
and fix the module. Exit is non-zero if anything reverted.

## Use it

On PATH via `~/.local/bin`:

```bash
comments-list src/ .github/workflows        # path:line:col: text  -- read this, decide
comments-strip src/foo.ts:12,48 .github/workflows/ci.yml:31
```

`comments list` and `comments strip` work too — all three run the same
`comments.py`.

`list` prints one line per comment and nothing else, so a whole directory's
comments cost a few hundred tokens to review — no file reads. `--all` also
shows KEEP-protected directives, marked; `--json` for programmatic use.

`strip` removes only the comments **starting** on the lines you name, so a
multi-line block comment needs just its first line. Unnamed comments are left
alone, and a line with no comment on it is a no-op rather than an error.

For a tree that genuinely wants zero comments, `--all` takes everything
strippable and its positionals become paths (default `.`) rather than
`FILE:LINE`:

```bash
comments strip --all --check src/       # what would go
comments strip --all src/
```

`--check` reports without writing, in either mode. `--collapse-blanks` also
closes a blank run left behind by a removal — never inside a string, here-doc,
or block-scalar body.

## Proving a module: `selftest`

The gate proves one edit. It cannot prove the *scanner*, since the scanner
also produces the normal form — a mis-framing identical before and after
passes. `selftest` attacks the module instead of the edit; run it against a
real corpus after any module change:

```bash
comments selftest .                       # every language with files here
comments selftest . --lang .rs --files 8 --mutations 8
```

Three checks:

- **coords** — every reported `(line, col)` must land on the reported text in
  the driver's frame (`str.splitlines(keepends=True)`), not a `\n`-only count.
- **keep** — every KEEP branch must actually fire against the corpus (the
  driver matches with `re.match` against the comment *including* its marker,
  e.g. `//`).
- **gate** — mutate non-comment, non-whitespace bytes; the normal form must
  move or raise. Any `BLIND` count is a normal form too lossy to be a proof.

Exit is non-zero if any module fails. `.js`/`.ts` are slow (a node process per
file), so scope them with `--lang` and a small `--files`.

## What it refuses to strip

Each language module has a `KEEP` pattern for comments that are **directives,
not prose** — removing them changes behaviour or tooling results. `# noqa`,
`# type:`, `# shellcheck`, `# yamllint disable`, `@ts-expect-error`,
`eslint-disable`, `prettier-ignore`, `#__PURE__`, `sourceMappingURL`,
`@license`/SPDX, `yaml-language-server:`, shebangs, coding declarations, and
more. In C# that also covers `///` and `/**` XML doc comments (compiled
output, not commentary) plus `// <auto-generated/>` and `// ReSharper
disable`. In Rust it covers all four doc-comment forms (`///` `//!` `/**`
`/*!` — they desugar to `#[doc]`, and can contain a doctest `cargo test`
runs) plus `//~ ERROR`, `//@` and `// SAFETY:`.
`strip` will not remove them even if you name their line; `list --all`
shows them marked so you can see what was skipped.

## Judging what to cut

The gate proves a strip is *safe*, never that it is *right* — that call is
yours. The bar: **keep only what the code cannot state about itself.**

- Keep: cross-file/external invariants, dependency gotchas, and the reason a
  filter excludes a case that otherwise reads as a bug.
- Cut: anything restating its own line or already explained by a nearby
  error/throw. When in doubt, cut — a stale comment misleads silently.

## Traps

- **The blank-run collapse is the recurring bug.** Collapsing `\n\n\n`
  file-wide also collapses blank lines *inside* strings. Get `protected_lines()`
  right for any new language before enabling `--collapse-blanks`.
- **A `#` is not always a comment.** YAML block scalars (`run: |`), here-docs,
  `${x#pat}`, `$#`, `a#b` plain scalars — modules are scanners, not regexes.
- **Trailing shell comments are never reported, by design** — a mid-line `#`
  needs full quoting context to classify safely.
- **`--all` doesn't know your conventions** — it will take load-bearing
  non-directive comments (e.g. `# v7` tags beside sha-pinned Actions). Use
  `list` + targeted `strip` outside a tree that truly wants zero comments.
- **TypeScript must be resolvable.** `.ts`/`.js` normalisation shells out to
  the `typescript` package, resolved upward from the file's own directory.
  With none reachable, those files are skipped rather than stripped unproven.

## Adding a language

Drop a module in `lang/`. The driver owns all excision; a module only supplies
knowledge:

```python
EXTS: tuple[str, ...]
KEEP: re.Pattern | None
def comments(src) -> list[tuple[line, col_start, col_end, text]]   # 1-based line, 0-based cols
def protected_lines(src) -> set[int]        # lines whose blankness is content
def normalize(path) -> str                  # comment-free normal form; RAISE if unparseable
```

For a multi-line comment, `line` is its first line and `col_end` its end column
on its last; the driver derives the last line as `line + text.count('\n')`.
`normalize` must never fall back to a weaker form — a file that cannot be proved
is a file that does not get stripped.
